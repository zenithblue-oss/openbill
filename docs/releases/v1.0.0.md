# OpenBill v1.0.0

First stable release. It adds scale work on top of the 1.0 feature-complete scope of 0.3.0-alpha.

## Upgrading

The database schema is now version 11. OpenBill makes an automatic backup before migrating an
older database, and shows progress at start-up. On a very large book (7 GB in our test) that
backup takes most of the migration time (about 13 minutes); the index build itself takes about
35 seconds. Make your own backup first if the data matters.

## What is new

- Scale: tested at 1,000,000 sales invoices, 200,000 purchase bills and 300,000 payments.
  Lists are paged in SQL, new indexes cover the common queries (schema v10) and the stock
  costing walk (schema v11).
- Reports: registers and Tally XML are streamed, outstanding/ageing is computed in SQL, and
  every report runs under a 512 MB heap. The on-screen sales and purchase registers are paged.
  Numbers are in docs/14-performance.md.
- Progress: long reports, exports, backup, import and start-up show a progress overlay (bar with
  count when the total is known). Reports and exports can be cancelled. Counts are grouped in
  Indian style.
- Fixes: ship-to GSTIN shown in one-line ship-to rows on PDFs; desktop restore no longer leaves
  the app running on a closed database.
- CLI: hidden `openbill dev` commands generate scale test data.

Versions: Android 1.0.0 (code 7), desktop 1.0.0, CLI 1.0.0.
